# AI CHAT HANDOFF — AGX1:C

Этот документ передаётся ИИ в начале нового чата, в котором используется Agent ChatAI Bridge.

## Правила AGX1:C

1. Для каждой новой команды используй контейнер AGX1:C.
2. Каждый AGX1:C должен содержать: session_id, message_id, action, args, timestamp, ttl.
3. session_id — идентификатор текущей сессии Agent ChatAI Bridge. Используй тот session_id, который сообщил пользователь.
4. Если пользователь сообщает новый session_id, с этого момента используй новый ID.
5. Если ты забыл session_id, попроси пользователя сообщить его снова. Пользователь может скопировать его кнопкой в окне Agent ChatAI Bridge.
6. message_id генерируй самостоятельно для каждой новой команды: ровно 32 hex-символа (пример формата: a1b2c3d4e5f60718293a4b5c6d7e8f90). msg_001 — неверный формат.
7. Не повторяй уже использованный message_id для новой команды.
8. action — имя разрешённого действия.
9. args — JSON-объект аргументов действия. Если аргументов нет, используй {}.
10. timestamp — текущее Unix-время в секундах с дробной частью на момент создания команды. Не копируй примеры из документации.
11. ttl — число секунд, достаточных для доставки и обработки; максимум 300. Больше — Gateway вернёт COMMAND_TTL_EXCEEDED.
12. Не добавляй в AGX1:C секретные или приватные ключи.
13. Не изменяй структуру контейнера и не придумывай дополнительные поля без отдельного правила.
14. Перед отправкой команды проверь, что в payload присутствуют актуальные session_id, message_id, timestamp и ttl.

## Формат payload

payload — канонический JSON: ключи отсортированы по алфавиту, без пробелов, UTF-8:

{"action":"<action>","args":{},"message_id":"<32 hex>","session_id":"<session_id>","timestamp":<unix-время>,"ttl":<секунды>}

Контейнер имеет вид:

AGX1:C:<base64url(payload)>:<sha256>

где sha256 — полная SHA-256 строки `C:<base64url(payload)>`, ровно 64 hex-символа, нижний регистр. Укороченный или выдуманный тег приводит к тому, что Bridge вообще не распознает команду.

session_id и message_id являются идентификаторами, а не секретами.

Команда без timestamp/ttl, с message_id не-32-hex или с тегом короче 64 символов не будет выполнена.

## Начало нового чата

В начале нового чата пользователь должен передать этот HANDOFF и актуальный session_id.

После получения нового session_id считай его текущим идентификатором сессии до тех пор, пока пользователь не сообщит другой.

## Важное правило ответа

Когда пользователь просит выполнить действие на ПК через Bridge, обычный ответ ИИ может содержать краткое сообщение по сути, а затем валидный AGX1:C или блок команд.

Не заменяй AGX1:C обычным описанием команды, если пользователь ожидает выполнение через Bridge.
